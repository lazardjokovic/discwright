DiscWright Test Matrix

0.12.0 0 of 0 by hand

Every case below is something a person can actually do to this program, taken from what the code branches on rather than from what sounds plausible. Ticks are kept in this browser, so a pass can be left half finished. Sections B, C, D and K are about the window itself and apply to every scenario between them: what has to move when you change something, what is live and what is grey, what happens when you try the thing that should not be there, and whether what it says still reads right at none and at one as well as at many.

68 of these are now run by the suite and are hidden. They are still here, because this is a map of everything the program can be asked to do and a map with roads missing is worse than a long one, but a pass by hand should only be the part a person has to do. Turn them on with the switch above and each says which test runs it.

A

What varies

Ten axes. The product of all of them is in the millions, which is why the lists below are a covering set rather than a grid. Two of the axes collapse usefully, and both are noted.

AxisWhat it can be
The ten axes are written down once, in tests/by-hand/a-disc.pict, and PICT turns them into the forty rows that cover every pair of values. EveryKindOfDisc runs all forty. This table is the reading of it.
Kind of folderA GOG download (one setup_*.exe and its numbered .bin parts), a folder of files with something runnable, or a folder of files with nothing runnable. You do not choose this; the recogniser does, GOG first.
What a folder of files runsThe menu runs an executable only when the folder has exactly one worth running, after unins, vcredist, dxsetup, dotnetfx and oalinst are struck out. With more than one it asks, and the answer narrows it to that one. With none, or with an answer of no, the menu copies the folder and opens it, and the window says which games that will be.
Games on itNone, one, two, several. Same name twice is its own case.
Patches and add-onsOnly ever from a GOG folder. The files recogniser takes everything in the folder, so nothing is left behind and there is nothing to offer as an add-on. This collapses a whole branch of the matrix.
TicksAll on; something off; the installer off; the game off with its add-ons still on.
ArtworkDisc icon, menu background (plus Stretch to fit), cover, disc face. Four independent choices.
ExtrasManual, extras folder, loose files, music. Manual, extras and loose files ride one disc of a set. Music rides every disc.
More optionsA menu, a checksum list, Windows 98 and Mac OS 9 readability, splitting a file too big for one disc.
Size of discCD-R 700 MB, DVD5 4.7 GB, DVD9 8.5 GB, BD-R 25 GB, BD-R DL 50 GB, BD-R XL 100 GB.
DrivesNone, one, two. Each empty, holding a blank, holding a used rewritable, holding a full disc, or holding a pressed film. Able or unable to shut its own tray.
Where it buildsSuggested from the first game, chosen by hand, or changed afterwards. Nothing is remembered between sessions.

D

Trying what should not be available

Found here, and since fixed

Only the buttons used to go dead during a run. Every input that changes the disc stayed live, so the window could be made to describe a plan for something other than the thing being written. Nine of them are held now: the list, the name, the size, the split box, the drive, where the ISO goes and all three More options.

Half the work was making them look held. Bound and left alone they stayed in exactly the ink of a live control, and a trigger setting the colour did not reach them either. So D3 to D8 are now cases where you confirm it, and D19 is the one that matters: does a held control look held.

E

Games, patches and what actually runs

Both of these are now fixed, and these are the cases that prove it

It asks now. A folder of game files with more than one executable worth running gets a question, and the answer narrows it to that one. One candidate is not a choice and none is not a question, so neither is asked about. Saying no is allowed.

And the window says which games it will only copy. E12 and E14 used to be the same disc wearing two different folders with nothing to tell them apart; now E14 asks, and if you decline, the window says so in ordinary ink beside the list.

The second one is on the window too. An unfinished download (INCOMPLETE: installer part(s) -3 are missing) and a folder holding several installers were both worked out from the first day and shown to nobody. They are beside the list now, in amber, for as long as the game is on it, rather than in a box that is dismissed an hour before the burn. E10a and E10b.

J

Refusals and awkward input

A refusal should say what is wrong, show the figures, and offer the way out. Red is for a wall; amber is for something true that is not a wall. Fewer things are refused than you would guess: a folder is turned away only when it is empty.

K

Every sentence, at none, at one and at many

Almost everything this program says counts something, and a sentence that reads perfectly at three reads wrong at one. Drive each of these to all three states and read it out loud. Singular and plural are the whole of it, but so is a sentence that is still true and no longer the point.

L

Known, and not fixed

Not worth reporting again unless the behaviour has changed.

  • Nothing is remembered between sessions. Where it builds is suggested fresh from the first game each time, and More options go back to a menu on, a checksum list on, Windows 98 off and splitting off.
  • Nothing on the disc's own menu can be driven by a test. An HTA is invisible to UI Automation, so every case in C41 to C49 and D15 is by hand or not at all.
  • A disc that fails its read-back may be the disc, not the program. A CD-RW with bad regions fails the same two files after a full erase and a fresh write. Try a different blank before reporting a burn.
